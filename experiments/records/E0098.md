# E0098 — Hierarchical XML arithmetic synthesis

Planned M4 prototype IXT2. Three contiguous page-aligned held-out regions of at least 1 MiB starting near 100M, 400M and 800M. Train 128-entry exact byte dictionary on disjoint initial page region. Build lossless lexical tree with explicit tag/gap leaves and verify ordered contiguous child partitions, preserve incomplete tails in fixtures. Root forced to concatenate page/gap objects, all internal objects choose shortest complete serialized node among allowed alternatives: raw bytes, dictionary ref, child concatenation, optional raw DEFLATE, and optional exact decimal radix conversion or prime-power times quotient (fixed 25 primes, <=64-byte spans). No costly new factor search. Decimal digit width preserves leading zero digits; integer operand width preserves leading zero bytes. No hidden parser state in decoder. All node tags, lengths, dictionary, references, operands and framing counted. Native zlib is conventional hybrid control, not number-theoretic novelty; executable size not counted. Three modes: structural-only, structural+DEFLATE, structural+DEFLATE+arithmetic; compare complete gzip/DEFLATE controls. Archive-level SHA and exact decode, trailing/truncated rejection, selected node counts, synthetic arithmetic selection fixtures. Decoder uses byte concatenation as exact implementation of radix synthesis, not materialization of an enormous BigInt. Same-code proof-of-concept; independent decoder remains M5. Root forced structural for fair matched ablation; not globally optimal among unrestricted trees. Corpus-specific lexical parser, not general XML validator. Sample result only, no full target claim. Standard hosted CI, 600 s cap, Node heap 3 GiB. If arithmetic gains are weak, investigate article-body subdivisions and repeated arithmetic expressions at meaningful scale rather than repeat small factor search.
