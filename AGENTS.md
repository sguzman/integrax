# Integrax operating protocol

Mission: discover rigorous, useful arithmetic descriptions of large integers, especially enwik9. The owner delegates research direction, implementation and campaign selection. Prefer whole-integer methods; allow blockwise and hybrid controls. No expenditure, external submission, access changes or mission changes without owner approval.

Start each conversation with STATE.md and AGENTS.md only. Read targeted sections of the active campaign, registry, frontier and experiment records as needed; do not load entire histories, inventory shards, diffs or CI logs into conversational context. Filter large tool results in code to counts, identifiers, relevant lines and verification results; process factor data programmatically. STATE.md is the authoritative compact, self-contained resume checkpoint: replace stale status rather than append a running log, target under 5,000 characters, link exact pending CI runs and evidence, and archive superseded history before removing it. Every meaningful checkpoint must be persisted and read back from GitHub; no dependency on chat exports. Preserve the owner-approved experiment scope and exact acceptance gates. "Continue" authorizes the next unfinished milestone and scientifically justified subsequent checkpoints within the available execution budget. Persist artifacts and state at each meaningful checkpoint and verify remote readback. Close completed or exhausted campaigns with evidence and autonomously select the next productive question. Campaign closure alone is not mission termination. Never invent work to prolong execution. Stop at owner request, mission acceptance, genuine exhaustion/blocker or practical turn limit. ALL DONE is reserved for genuine mission termination or necessary owner intervention, not routine milestones.

Integrity: count all operands, residuals, signs, opcodes, boundaries, models, transforms and executable/side information. Exact bytes, no decoder oracle, network, or original corpus. Report archive size separately from contest total. Distinguish proofs, conjectures, empirical evidence and contest eligibility. Check prior art before novelty claims; preserve negative results. Record input hashes, commands, seeds, environment, revision, outputs, runtime and memory. Never claim execution or verification without evidence.

Prefer Rust and Nix; no npm. Preserve the owner-authorized competition-restricted development license, historical MIT grants and third-party notices. Owner authorized restoring public visibility and GitHub-hosted CI; no external contest submission without explicit owner authorization. Use GitHub-hosted Actions as primary CI once public and enabled; do not incur paid runner spending or require owner-run wrkflw. Keep local tooling and partial downloads intact as optional historical fallback. See docs/HOSTED-CI.md. Disclose AI assistance and review status in papers. README stays concise and stable, never a running log. Use CHANGELOG.md and separate campaign notes, keeping STATE.md compact.

Lead owns main and acceptance. Workers, if assigned, use isolated branches and explicit scopes in COORDINATION.md. Check branch head before writes; no force pushes. Report actual changes, remaining work and human action.
