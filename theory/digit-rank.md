# Digit-rank arithmetic descriptions

Let a byte string x of length L have sorted distinct alphabet A=(a_0,...,a_{m-1}). Replace each digit x_i by its index d_i in A. The base-m rank R=sum_i d_i m^(L-1-i), with (L,A,R), uniquely represents the original integer. For m>=2, 0<=R<m^L; base-m expansion padded to L digits inverts exactly. For m=1 the rank is zero; for L=0 encode empty explicitly. A power-of-two alphabet admits streaming fixed-width packing of ceil(log2 m) bits/digit; non-power-of-two radix requires efficient conversion or an equivalent interval method. The ideal rank uses ceil(L log2 m) bits, not including length, alphabet or framing. If m=256, uniform rank gives no gain.

For histogram n_a and fixed length L, the count of strings with that histogram is M=L!/prod_a n_a!. Lexicographic rank in this class is bijective with integers 0..M-1. At each position the number of remaining sequences beginning with a symbol a is M*n_a/L, an exact integer. Choosing the symbol partitions the interval by these counts, yielding exact rank/unrank via integer arithmetic. Charge the histogram (or equivalent model), length and rank. For large L, Stirling's estimate gives log2 M approximately L*H(n/L) plus lower-order terms. This describes potential cost, not measured results. Naively materializing enormous multinomials or ranks is expensive; finite-precision arithmetic/range coding implements closely related interval ideas, but is not automatically the exact multinomial rank. Label the actual representation and overhead.

These constructions are established enumerative/entropy-coding ideas, not novelty claims. The initial goal is a genuine full-enwik9 lossless arithmetic description and a measured compression frontier, before more speculative arithmetic circuits or transformations.
