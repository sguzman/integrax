# Canonical arithmetic payload verification

The arithmetic encoder is a deterministic transducer of the decoded binary decisions and their pre-update count weights. Given the same initial interval and every decision, induction gives identical encoder interval and pending-underflow state after each renormalization. The decoder can replay these decisions directly into a second encoder, sharing the existing predictive model instead of storing another model or reconstructing the greedy parse. At termination, the second encoder emits the unique prescribed payload bytes for that decision sequence. Comparing these bytes to a separate reader, including EOF, rejects every noncanonical payload for that sequence. The comparison uses bounded buffers and retains no root stream. In particular appended bytes are rejected even when they do not affect decoding. A strict decoder need not enforce that the original encoder chose greedy matches, because alternative decompositions are explicitly represented.

A canonical encoding is not an authenticated encoding. An arbitrary damaged archive might be canonical for a different valid root sequence or header, and the decoder cannot know the intended original without a charged checksum or trusted external digest. This check therefore does not imply rejection of every truncation or bit flip, and does not retroactively change earlier archive records. Output is provisional until successful exit. Two readers assume an immutable file during decoding. The benchmark measures extra runtime and memory, compares the exact output, and checks append rejection; independently compares the strict output hash. No novelty claim.
