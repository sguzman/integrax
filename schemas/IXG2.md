# IXG2 global arithmetic DAG

Header: magic IXG2, mode byte (0 fixed-width roots, 1 Huffman roots), u64 BE original byte length (<=1,000,000,000), u16 BE rule count n<=16384, n pairs of u16 BE symbol IDs. IDs 0..255 are fixed byte literals; rule i defines 256+i by concatenating two earlier symbols. Each expansion <=256 bytes. All rules charged, including unused training rules. Mode 1 additionally stores one canonical unsigned LEB128 root frequency for each of the 256+n symbols. Build a binary Huffman tree using a min-heap keyed by (weight, minimum leaf ID, creation ID); first popped node is left/0, second right/1. Single leaf uses zero bits; empty stream has no tree. Fixed mode root width ceil(log2(256+n)). Bits MSB-first, final unused low bits zero. No extra payload length: decode roots until exactly original byte length, validate weighted frequency total and actual counts in Huffman mode, reject nonzero padding or trailing bytes. No external dictionary at decode.

Training: at most 512 KiB sample, repeated maximum-frequency nonoverlapping pair replacement among eligible expansions <=256, ties by ascending pair ID, <=16384 rules (default budget 1024). All 256 byte literals always available. Encode with global trie longest match, ties by lowest existing ID for duplicate expansions, parse continuously across read-buffer boundaries. Two passes compute frequencies and then encode. Archive-only comparison; no raw fallback in this experimental format. Memory bounded by dictionary size, trie, Huffman tree and fixed buffers. Unauthenticated; external SHA-256 and exact comparison required. Ordinary dictionary/Huffman coding with arithmetic concatenation semantics, not new mathematics.

The original E0025 archive used 1024 rules and remains compatible. The implementation cap has been raised for experiments, not a new wire format; older decoders reject larger dictionaries. Rule count and IDs remain u16.

## Extension: mode 2 (aligned roots)

Mode 2 stores each greedy root ID as a big-endian unsigned 16-bit integer, with no frequency table. Header and dictionary are identical to mode 0; decode until the original length, validating IDs, exact output length and end of input. Older decoders reject this mode. It is intended as an intermediate reversible representation for independently charged hybrid backends. Modes 0 and 1 are unchanged.

## Extension: native adaptive modes 3 and 4

Modes 3 (adaptive) and 4 (context) store the same length and DAG header as mode 0, followed by an arithmetic-coded bit stream of greedy root IDs, each represented as w=ceil(log2 K) binary decisions. No frequency table. At each bit decision, use the counts for the current binary prefix node p (start 1; update p=2p+b); mode 3 has a single context, mode 4 has 257 contexts: last expanded byte 0..255 and start 256. Initialize all binary count pairs to (1,1), increment observed bit, halve both with ceiling when sum reaches 4096. Update context only after the complete root. Binary tree stride 2^w. Interval initialization [0,2^32-1]; split at lo+floor((hi-lo+1)*count0/total), then standard E1/E2/E3 arithmetic renormalization and pending underflow bits as IX04. Terminate with one additional pending bit, emit 0 if lo<2^30 else 1, then opposite pending bits; pad last byte with zero bits. Empty original has no payload. Decoder initializes 32-bit code, allows up to 32 virtual zero bits on EOF, expands until exactly L bytes; reject invalid root IDs, output overshoot, impossible arithmetic interval or excessive virtual padding. This experimental arithmetic payload is not canonicality- or integrity-checked at end; external digest and exact comparison required, as with IX04. Older decoders reject modes 3/4. No separate model or training corpus required at decode. Both modes use same dictionary and greedy parse, not external backend.

## Extension: mode 5 (context backoff)

Same frame, root parse, binary interval engine and local context table as mode 4. Also maintain one global binary count pair per prefix node, initialized and rescaled exactly like local counters, updated after every bit. With local counts (c0,c1), global counts (g0,g1), use integer zero weight c0*(g0+g1)+32*g0 and total (c0+c1+32)*(g0+g1). Both tables updated only after coding/decoding a bit. No additional bytes besides mode selector; fixed prior strength 32 is a format constant. Older decoders reject mode 5. Same termination limitations as modes 3/4.

## Extension: modes 6–8, lexicographic ranks and second-order suffix contexts

Mode 6 is mode 4 except that root IDs are replaced by their ranks in the lexicographic ordering of expanded byte strings, ties by increasing original ID. Decoder derives the identical permutation from the charged dictionary. Mode 7 uses these ranks plus a tagged two-byte suffix context; mode 8 uses original IDs plus the same suffix context. For modes 7/8 maintain last two output bytes (initial pair 256,256); advance by complete expansion, including the penultimate byte of a multi-byte root. At each prefix node p compute key = (older*257+last)*stride+p+1. Fixed 2^21 tagged slots, empty tag zero; index by xor-shift/multiply hash defined in source (32-bit wrapping multipliers 0x7feb352d and 0x846ca68b, shifts 16,15,16; mask low 21 bits). On tag miss, predict using the existing one-byte context counts. On tag hit with counts a0,a1 and one-byte counts c0,c1, use zero weight a0*(c0+c1)+8*c0, total (a0+a1+8)*(c0+c1). On miss replace slot with (key,1,1) then increment observed bit; on hit increment existing counts. Update order-one table as mode 4. Same count rescale. All model state decoder-derived; no transmitted table. Modes 0–5 unchanged. Termination limitations unchanged.

## Extension: modes 9–10, deeper tagged predictors

Both inherit mode 7 lexicographic ranks and order-one/two-byte predictions. Additional 2^20 direct-mapped tagged entries (u64 tag and u16 counter pair). Mode 9 key context is the three last output bytes, initial all 256, indexed as (oldest*257+older)*257+last. Mode 10 key context is previous original root ID, initial K. Key=context*stride+p+1. Hash using wrapping u64 xor-shift/multiply constants 0xbf58476d1ce4e5b9, 0x94d049bb133111eb and shifts 30,27,31; low 20 bits. On hit, first quantize the order-two zero probability to floor(4096*z/n) clamped 1..4095, then combine deep counts with eight pseudo-observations from that quantized probability: zero=a0*4096+8*zq, total=(a0+a1+8)*4096. On miss use unchanged order-two prediction. Both lower tables updated as mode 7; deep slot reset to (1,1) on miss, increment observed bit. Context advances after whole root, retaining last three bytes across root boundaries and previous original root ID. No transmitted model. Older modes unchanged, same payload integrity limitations.

## Strict arithmetic decoding

Optional CLI `decode-strict ARCHIVE OUTPUT` for modes 3–10 regenerates the canonical arithmetic stream from the actual decoded root decisions using the same pre-update integer weights, then compares every generated byte against a separately positioned reader of the original payload, including exact end of file. It rejects noncanonical representations of the decoded sequence and surplus bytes, without changing the frame or adding metadata. Modes 0–2 use their existing strict decoder. Output may have been written before an error is reported; callers must check the exit status and discard failed output. This is not a checksum or authentication: a modified frame that is canonical for another valid root sequence can pass. External original/archive SHA-256 and exact comparisons still required. The input file must not change during verification.

## Larger dictionary cap

The experimental cap is now 16384 rules, 512 KiB training. Existing archives and mode semantics unchanged; old decoders reject larger dictionaries. At K<=16640, stride<=32768, order-two key maximum 257^2*32768=2164293632 fits u32, with nonzero tag. Deep keys remain u64. All grammar rules charged. Larger alphabet may worsen contextual coding; measured ablation required.

## Extension: modes 11–12, full binary root trees

Both modes retain mode 9's third-order suffix model, except the binary decision tree is no longer the fixed-width rank tree. Sort all K roots lexicographically by expansion, ties by original ID. Recursively construct a full binary tree on ordered subranges: mode 11 splits the first eight levels by successive bits of the first expanded byte (MSB first; every byte has a literal, hence both branches exist), then splits each remaining non-singleton subrange at floor(count/2). Mode 12 uses the median-count split at every level. A singleton is a leaf with the original root ID. Number internal nodes 1..K-1 in preorder (left before right); use these numbers as binary probability node indices instead of heap indices. The model's stride is still 2^ceil(log2 K). Encode/decode a path until its leaf; no invalid ranks, no model/tree bytes transmitted. Both use the last-three-byte deep key, not previous root. Greedy parse unchanged. Canonical strict verification supported. Older decoders reject modes 11/12.

## Extension: mode 13, decoder-derived recurrence

Mode 13 uses mode 12 median tree and root model, with an additional history ring and last-occurrence table of 2^20 entries each. Maintain absolute output position pos, last four digits as a rolling u32 key (big-endian), and candidate distance d. After each output byte, update key and pos, reset d to zero; if pos>=4, use slot_index(key,2^20-1), retrieve tagged previous position q if nonzero, matching key, and 0<pos-q<=2^20; set d=pos-q; then replace the slot with (key,pos). Ring stores last 2^20 bytes. Candidate distance is fixed for the next token. At each token boundary, if d>0 encode a copy flag with an adaptive count pair indexed by last byte (initial 1,1, existing rescale); if d=0 no flag. Flag 0 or unavailable candidate: encode a normal median-tree root as mode 12, update its model and feed every expanded byte to history. Flag 1: eight equiprobable bits represent length minus 16 (valid 0..240); copy exactly that many plus 16 bytes from distance d, allowing overlap. Feed each copied byte to history; advance root model suffix by copied bytes, but do not update root decision counts for uncoded roots. Reject length overshoot. Encoder selects longest exact match up to 256 bytes if >= configurable minimum 16 or 32 and >=2 times longest dictionary root length. Encoder-only thresholds not transmitted. Strict canonical mirror supports all decisions. No external side data or distance operand. Older decoders reject mode 13.

## Extension: mode 14, adaptive recurrence lengths

Identical to mode 13 except eight bits of length minus 16 use adaptive count pairs keyed by floor(log2 d) (0..20) and binary prefix node p (1..255). Initialize (1,1); update and rescale as existing binary models. Reset p=1 for each copy, advance p=2p+b. Distance is decoder-derived and fixed during length coding. No extra table bytes transmitted. Threshold 16 or 32 encoder-only. Strict decoder mirrors all decisions. Older decoders reject mode 14.

## Extension: mode 15, two decoder-derived recurrence candidates

Mode 15 inherits mode 14. Each tagged four-byte context slot additionally remembers the second-most-recent endpoint (zero absent). On each byte update, retrieve the prior newest endpoint as in mode 13, and retrieve the prior second endpoint only when newest is valid and second is nonzero within W=2^20 bytes. Then set second endpoint to the old newest position if the tag matched, otherwise zero; overwrite newest as usual. On a recurrence flag 1 with two valid distances, code selector 0=newest, 1=second, using adaptive pairs indexed by last output byte, initialized (1,1), existing update/rescale. If only one distance, omit selector. Length model uses selected distance. Encoder matches both candidates, picks greater match length (ties newest), applies same minimum and >=2*longest root test. Both candidates are derived, selector is charged. Decoder copies exactly selected recurrence; strict mirror includes selector. Older decoders reject mode 15.

## Extension: modes 16–17, longer recurrence context

Identical to mode 15 except recurrence context keys use the last six (mode 16) or eight (mode 17) output digits as a rolling big-endian u64, masked to context length. No candidate before enough bytes. Slot index uses wrapping u64 hash as the existing deep predictor (xor shifts 30,27,31, multipliers 0xbf58476d1ce4e5b9 and 0x94d049bb133111eb, mask low 20 bits). Store and compare the entire key, so collisions evict rather than merge contexts. Two endpoints, distance cap, flags, selectors, adaptive lengths and root model unchanged. Modes 13–15 retain original four-byte key and u32 hash; wire bytes unchanged. Encoder threshold 16. Older decoders reject modes 16/17.

## Extension: mode 18, one sparse recurrence correction

Identical to mode 15 except after each copy length, encode a patch flag using adaptive pairs indexed by last output byte (initial 1,1, same rescale). If 1, encode two unsigned eight-bit values, position j and modular residual e, equiprobable MSB first. Reject j>=length or e=0. Copy sequentially at selected distance, adding e modulo 256 to the referenced digit exactly at j before appending it to history; future overlapping references see the corrected digit. Flag 0 gives ordinary exact copy. The encoder selects a candidate with at most one mismatch, requiring at least eight subsequent matching digits, minimum length max(32,threshold), >=2*longest root+8, and length minus 24 strictly greater than best exact length (ties preserve earlier candidate). Encoder-only heuristic; no format overhead other than mode and charged patch decisions. Strict replay includes all bits. Older decoders reject mode 18.
