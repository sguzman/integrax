# C20 — XML-guided hierarchical arithmetic synthesis

Active; owner explicitly approved 2026-11-26 UTC. Goal: reconstruct the exact whole enwik9 integer bottom-up by composing number-theoretic descriptions of XML elements, bodies, and all interstitial lexical bytes. No requirement that leaf factors divide the parent integer. C19 mode8 is independently verified and preserved as a deferred competitive candidate; no full-corpus integration until resumed.

## Model
For a byte span s of length l, I(s) is its big-endian integer with length retained. I(a||b)=I(a)*256^len(b)+I(b). A parent is a partition into literal opening/closing tag bytes, child spans and interstitial lexical bytes, not an overlapping concatenation of both a parent and its children. Exact whitespace, attributes, entities, comments, CDATA, XML prefixes, and incomplete final markup are preserved. Do not use a semantic parser that normalizes text and then reserializes. A raw fallback must cover unparsed bytes. Optimize tree cost with min(raw, arithmetic leaf, ordered child expressions plus all framing), not local factor count. Prime factors are components of leaf expressions, not necessarily factors of the root. Factor storage includes primes, exponents, operand widths, tags, dictionary and references; only actual smaller serialized archives count as compression.

Mathematical interpretation: for a byte concatenation A||B with |B|=k and an odd prime p, I(A||B)=I(A)·256^k+I(B), and 256^k is invertible modulo p. Thus p divides the parent exactly when I(B) ≡ −I(A)·256^k (mod p); a child factor does not automatically divide its parent. Under a uniform-residue heuristic this event has probability about 1/p, but real corpus residues are structured and this is not a corpus law. E0128/E0129 show measurable reuse in lexical and mid-level values, with weak article/page propagation and side-information costs far exceeding the removed bit counts. This remains empirical and is not evidence of useful archive compression.

### Mathematical and storage interpretation
For big-endian byte strings, concatenation satisfies `value(A || B) = value(A) * 256^|B| + value(B)`, not a product relation. If an odd prime `p` divides `value(A)`, it divides the parent only when `value(B) ≡ 0 (mod p)`; divisibility does not follow from byte/object subsumption. Child factors are therefore candidates requiring exact parent tests. E0137's page-scale population had 492 child-factor hits versus 5,173 global-inventory hits; its three page-root rows had no full-inventory reduction. The 113 E0138 refinements are empirical modular coincidences across old and new rows, not a monotone inheritance law.

There is, however, a certified child-intersection case. For immediate children `C_i` with integer values `n_i` and byte widths `w_i`, the parent value is `N = Σ_i n_i 256^{Σ_{j>i}w_j}`. If every child is divisible by `p^e`, each summand is divisible by `p^e`, so `p^e | N`; the minimum child valuation is a provable inherited exponent. A factor found in only some children has no such guarantee. Corrected E0143 measured this rule against frequency-ranked checks: exact products matched, but the direct intersection implementation was ~7× slower while avoiding only 0.63% of parent modulo checks. Faster indexed intersections remain untested; this negative result is specific to the tested implementation and sample.
